This is a Confluence playbook ("Hive to Iceberg Migration Playbook") for automating the migration of on-prem Hive-based applications to Iceberg tables on AWS, using GitHub Copilot's Agent mode as the automation engine. Here's the gist:

What it does
It's essentially a prompt-driven automation kit. You feed Copilot (running in Agent mode, using a Claude model) a set of reference files, and it generates the migration artifacts for you instead of you writing them by hand.

Setup

IDE: IntelliJ IDEA (recommended for Scala), VS Code, or PyCharm, with GitHub Copilot enabled
You create an ICEBERG_MIGRATION folder under src/main and drop in:
Iceberg_Migration_Agent.md — the playbook/instructions file itself
JIL.txt — job scheduling definitions
Job_Properties.txt — ORAAS properties
Job_Scala_File_Mapping.txt — maps jobs to their Scala source and end tables
Table_metadata.csv — table schema/metadata
How you run it
In Copilot's Agent chat, you attach the Iceberg_Migration_Agent.md file plus the specific Scala file you want migrated, then give it a natural-language prompt, e.g.:

"Refer Iceberg_Migration_Agent.md and migrate [file].scala alone and its relevant DDL/ORAAS/JIL"
"Refer Iceberg_Migration_Agent.md and Generate DDL's alone for the end tables in Job Scala mapping"
What it outputs

Iceberg-compatible DDL scripts
ORAAS configuration files
JIL scripts (job scheduling)
Migrated Scala code files
Important safeguard: it doesn't overwrite your existing source — it generates new files alongside the originals so developers can review/validate before merging into the main codebase.

Current scope: fully working for apps built on the "Step Framework." They're still extending it to cover the "DC Framework" and testing ALTER TABLE scenarios where existing data needs to be preserved during migration.
